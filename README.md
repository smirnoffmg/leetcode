# leetcode

Решения задач LeetCode на Go и генератор заготовок `lcgen`, который тянет условие
задачи из публичного GraphQL API LeetCode и раскладывает по каталогу `problems/`
готовый пакет: README с условием, файл решения и таблично-ориентированный тест.

## Требования

- Go 1.26+
- bash, make

## Быстрый старт

```bash
make new S=two-sum   # заготовка по слагу задачи
make daily           # заготовка по задаче дня
make test            # прогнать все решения
make push            # закоммитить и запушить работу за день
```

Слаг — это часть URL задачи: `https://leetcode.com/problems/two-sum/` → `two-sum`.

## Что генерируется

`make new S=two-sum` создаёт каталог `problems/0001-two-sum/`:

```
problems/0001-two-sum/
├── README.md          # условие в markdown, топики, acceptance rate, подсказки под <details>,
│                      # похожие задачи и пустой раздел Idea для разбора и сложности
├── solution.go        # go-сниппет из leetcode; тела функций заполнены panic("not implemented"),
│                      # определения ListNode/TreeNode вынесены из комментариев в код пакета
└── solution_test.go   # табличный тест по metaData задачи: поля структуры — параметры функции,
                       # случаи заполнены примерами из условия
```

Имя пакета — слаг без дефисов (`twosum`); если слаг начинается с цифры (`3sum`),
добавляется префикс `p`.

Каталог существующей задачи не перезаписывается. Чтобы пересоздать:

```bash
go run ./cmd/lcgen -slug two-sum -force
```

### Про сгенерированный тест

Значения примеров разбираются как JSON и переводятся в литералы Go. Всё, что литералом
не выражается (деревья, связные списки, `any`), подставляется нулевым значением и
помечается комментарием `// TODO:` с исходной строкой из leetcode. Ожидаемые результаты
вытаскиваются из строк `Output:` в условии — их API не отдаёт отдельно, так что стоит
их перепроверять.

Если у задачи нет пригодной `metaData`, генерируется тест-заглушка с примерами
в комментариях и `t.Skip`.

## Работа без сети

Если leetcode недоступен, `lcgen` делает заглушку — но тогда номер и название взять
неоткуда, их нужно передать руками:

```bash
make new S=two-sum N=1 T="Two Sum" D=easy
```

Для `make daily` фолбэка нет: без ответа API задача дня неизвестна.

## Команды make

| Команда                                                | Что делает                            |
| ------------------------------------------------------ | ------------------------------------- |
| `make new S=<slug> [N=<num> T=<title> D=<difficulty>]` | заготовка по слагу                    |
| `make daily`                                           | заготовка по задаче дня               |
| `make test`                                            | `go test ./...`                       |
| `make cover`                                           | тесты с покрытием                     |
| `make bench`                                           | бенчмарки с аллокациями               |
| `make fmt` / `make vet` / `make lint`                  | форматирование и статические проверки |
| `make tidy`                                            | `go mod tidy`                         |
| `make push [M="<текст>"]`                              | закоммитить и запушить работу за день |

## Структура репозитория

```
cmd/lcgen/     генератор: клиент GraphQL, html→markdown, рендер файлов, маппинг типов
scripts/       обёртки new.sh и daily.sh, которые make дёргает
problems/      сгенерированные задачи, по одному пакету на задачу
```
