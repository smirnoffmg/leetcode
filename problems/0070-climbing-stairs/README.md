# 70. Climbing Stairs

- Difficulty: easy
- Link: https://leetcode.com/problems/climbing-stairs/
- Topics: Math, Dynamic Programming, Memoization
- Acceptance: 54.3%

## Statement

You are climbing a staircase. It takes `n` steps to reach the top.

Each time you can either climb `1` or `2` steps. In how many distinct ways can you climb to the top?

**Example 1:**

```
Input: n = 2
Output: 2
Explanation: There are two ways to climb to the top.
1. 1 step + 1 step
2. 2 steps
```

**Example 2:**

```
Input: n = 3
Output: 3
Explanation: There are three ways to climb to the top.
1. 1 step + 1 step + 1 step
2. 1 step + 2 steps
3. 2 steps + 1 step
```

**Constraints:**

- `1 <= n <= 45`

## Idea

### Что именно считается

Объект подсчёта — **упорядоченная последовательность** шагов по `1` и `2` с суммой `n`. Порядок существен: в примере 2 условия `1+2` и `2+1` перечислены как два разных способа. Это не деталь формулировки, а то, на чём стоит всё дальнейшее (см. ниже).

Состояние — одно число: номер ступеньки. `dp[i]` — сколько различных способов добраться ровно до `i`. Больше в состоянии ничего не нужно: как именно мы попали на `i`, на дальнейшее не влияет, будущее зависит только от того, сколько ступенек осталось.

### Рекуррентное соотношение

Пути в `i` классифицируются по **последнему** шагу — именно к этому подталкивает подсказка в условии. Любой путь непуст и кончается либо шагом `1`, либо шагом `2`, третьего варианта нет. Множество распадается на две части:

- путь кончается шагом `1`. Отбросив последний шаг, получаем путь в `i−1`. Операция обратима — по любому пути в `i−1` дописыванием единицы восстанавливается ровно один исходный, — то есть это биекция, и таких путей `dp[i-1]`;
- путь кончается шагом `2` — тем же рассуждением `dp[i-2]`.

```text
dp[i] = dp[i-1] + dp[i-2]
dp[1] = 1, dp[2] = 2
```

Складываются мощности, а не перемножаются, потому что части **не пересекаются** (последний шаг не бывает одновременно `1` и `2`) и **покрывают всё** (других значений шага нет). Это правило суммы: варианты взаимоисключающие, «или-или»; умножение появилось бы при независимом выборе двух признаков, «и-и».

Три условия, которые и делают вывод доказательством, стоит проверять у любой считающей рекурренты: части не пересекаются (иначе двойной счёт), покрывают всё (иначе недосчёт), соответствие с меньшей задачей обратимо (иначе мощности не равны).

Считать можно и от первого шага — `dp[i] = dp[i-1] + dp[i-2]` получится то же самое, поскольку задача однородна: после первого шага остаётся ровно такая же лестница меньшей высоты. Разбор по последнему шагу удобнее тем, что прямо ложится на восходящий цикл.

### База

`dp[1] = 1` и `dp[2] = 2` считаются руками. Эквивалентный вариант — начать с `dp[0] = 1`, где единица означает пустую последовательность шагов: единственный способ находиться в начале, ничего не сделав. Ноль на этом месте обнулил бы всю последовательность.

### Почему порядок шагов существенен

Если считать не последовательности, а **мультимножества** шагов (порядок неважен), та же формула становится неверной: для `n = 4` она даёт `5`, тогда как правильных ответов три — `1+1+1+1`, `1+1+2`, `2+2`. Ломается ровно проверяемое условие: у мультимножества нет «последнего шага», классификация перестаёт быть разбиением, и варианты считаются повторно. Задачи о разбиениях числа поэтому требуют второго измерения в состоянии — «ступенька + максимальный разрешённый шаг».

### Связь с Фибоначчи

Рекуррента и база дают `dp[n] = F(n+1)` при `F(1) = F(2) = 1`. Отсюда и ограничение `n <= 45` в условии: `dp[45] = F(46) = 1836311903` — последнее значение, влезающее в 32-битный знаковый int (`dp[46] = 2971215073` уже нет). В Go с 64-битным `int` это не ограничение, но объясняет выбор границы.

Второй, независимый способ посчитать то же самое — по числу двоек: путь с `k` двойками это перестановка `k` двоек и `n−2k` единиц, то есть выбор позиций двоек среди `n−k` шагов, а всего

```text
dp[n] = Σ C(n−k, k),  k = 0..⌊n/2⌋
```

Это известное тождество «суммы по пологим диагоналям треугольника Паскаля дают числа Фибоначчи». В тестах оно используется как эталон: выведено из определения задачи, а не из рекурренты, поэтому общей ошибки у них быть не может. Сверка идёт по всему диапазону условия — 45 значений, полное покрытие, случайные входы не нужны. На `n <= 20` ответ дополнительно подтверждается прямым перечислением последовательностей.

### Реализация

Прямой цикл по возрастанию `i`. `dp[i]` зависит только от двух предыдущих значений, поэтому таблица свёрнута в пару `prev, cur`, стартующую с `dp[0] = dp[1] = 1` (база с пустой последовательностью, см. выше). Каждая итерация сдвигает пару на ступеньку, после `n − 1` итераций `cur = dp[n]`; при `n = 1` цикл не выполняется, и отдельной ветки для малых `n` не нужно.

Это ровно тот случай, о котором пишет Кормен: восходящий DP позволяет «exploit the regular pattern of table accesses … to reduce time or space requirements even further» (*Introduction to Algorithms*, 3rd ed., с. 389). Порядок обращений к таблице фиксирован — только два последних значения, — и память падает с O(n) до O(1).

Для больших `n` та же рекуррента считается за `O(log n)` возведением матрицы `[[1,1],[1,0]]` в степень; при ограничениях этой задачи это лишнее.

- Time: O(n)
- Space: O(1)
