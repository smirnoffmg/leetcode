# Can Remove All

- Link: задача контестная; название и слаг взяты из имени функции `canRemoveAll` и могут отличаться от настоящих
- Contest: номер, сложность и ссылка на момент решения не опубликованы

## Statement

You are given three integer arrays `types`, `colors`, and `groupSize`, where `types` and `colors` have length `n`, and `groupSize` has length `m`.

- `types[i]` represents the type of the element at index `i`.
- `colors[i]` represents the color of the element at index `i`.
- `groupSize[t]` represents the required number of elements in a removable group of type `t`.

In one operation, you may remove **exactly** `groupSize[t]` **consecutive** elements if all of them have type `t` and the **same color**.

After each removal, the remaining elements become **adjacent** again while maintaining their relative order.

Return `true` if it is possible to remove all elements using a sequence of valid operations. Otherwise, return `false`.

**Example 1:**

```
Input: types = [0,1,1,0], colors = [5,3,3,5], groupSize = [2,2]
Output: true
```

**Example 2:**

```
Input: types = [0,1,0], colors = [9,9,9], groupSize = [3,2]
Output: false
```

**Example 3:**

```
Input: types = [2,0,1,2], colors = [7,5,4,7], groupSize = [3,1,2]
Output: false
```

**Constraints:**

- `1 <= n == types.length == colors.length <= 10^5`
- `1 <= m == groupSize.length <= 10^5`
- `0 <= types[i] <= m - 1`
- `1 <= colors[i] <= 10^5`
- `1 <= groupSize[t] <= n`

## Idea

Главный вопрос — важен ли порядок удалений. Перебор порядков экспоненциален, а жадность обычно ломается именно на нём. Здесь порядок не важен, и это можно доказать.

Будем считать пару `(тип, цвет)` буквой `x`, а операцию — переписыванием `x^g → ε`, где `g = groupSize[тип]`.

Возьмём две операции, применимые к одному слову:

- Если группы не пересекаются, операции перестановочны: удаление одной не мешает другой, и результат один.
- Если пересекаются, общий элемент делает их группами одной буквы с одним `g`, и обе лежат в одном блоке этой буквы. Удаление любой из них укорачивает блок на `g`, и слово получается одно и то же.

Каждая операция укорачивает слово, значит, процесс конечен. Конечная система, в которой любое такое расхождение сходится, имеет единственную нормальную форму (лемма Ньюмена). Поэтому от порядка ничего не зависит: удалить всё можно тогда и только тогда, когда пуста единственная нормальная форма.

Остаётся вычислить её стеком блоков `(буква, длина)`:

1. Новый элемент увеличивает верхний блок, если буква та же, иначе кладётся новым блоком.
1. Блок длины `g` снимается сразу.

После каждого шага у соседних блоков разные буквы, а длины меньше `g`, значит, удалить в стеке больше нечего: это и есть нормальная форма. Отдельно склеивать блоки после снятия не нужно: новый элемент просто продолжит открывшийся верхний блок.

Проверки только по числу элементов недостаточно: `x y x y` при `g = 2` содержит всех поровну, но удалить нечего. Этот случай есть в тестах.

Теорема проверена эталоном: он от определения перебирает все порядки удалений с запоминанием. Сверка идёт на 30 000 маленьких входов. Они строятся вставкой целых групп с порчей половины входов, потому что равномерно случайные последовательности почти всегда дают `false`. Тест требует минимум по 5000 ответов каждого вида.

Варианты замерены в одном бинарнике (`benchstat`, `-count=20`, Apple M2 Pro, `n = 10^5`):

| Вход           | блоки, упакованный ключ | то же без предвыделения | блоки, поля отдельно               | стек элементов                     |
| -------------- | ----------------------- | ----------------------- | ---------------------------------- | ---------------------------------- |
| `nested-pairs` | 160.6 мкс               | 291.3 мкс (+81%)        | 201.6 мкс (+26%)                   | 218.7 мкс (+36%)                   |
| `all-same`     | 230.0 мкс               | 202.1 мкс (-12%)        | 267.6 мкс (+16%)                   | 274.1 мкс ± 29% (+19%)             |
| `triplets`     | 223.5 мкс ± 28%         | 169.6 мкс (-24%)        | 225.5 мкс (незначимо, `p = 0.616`) | 251.1 мкс (незначимо, `p = 0.289`) |
| `random-stuck` | 177.0 мкс               | 482.7 мкс (+173%)       | 220.4 мкс (+25%)                   | 207.1 мкс (+17%)                   |
| память         | 1.5 МиБ                 | 0–8.5 МиБ               | 2.3 МиБ                            | 1.5 МиБ                            |

Там, где `p` не указан, `p = 0.000`.

Выбран стек блоков с упакованным ключом и предвыделением: у него лучший худший случай (230 мкс против 483 мкс без предвыделения) и предсказуемая память. Без предвыделения быстрее только при мелком стеке, где почти нечего выделять, а на полном стеке он почти втрое медленнее из-за 27 перевыделений. Замер `triplets` у базового варианта шумный (±28%), поэтому те две незначимые разницы ничего не доказывают.

- Time: O(n)
- Space: O(n)
