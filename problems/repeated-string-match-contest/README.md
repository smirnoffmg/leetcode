# Repeated String Match (contest)

- Link: задача контестная; название и слаг условные, функция называется `repeatedStringMatch`, а её сигнатура отличается от задачи 686
- Contest: номер, сложность и ссылка на момент решения не опубликованы

## Statement

You are given two strings `a` and `b` consisting of lowercase English letters, and two integers `x` and `y`.

Return `true` if the string formed by repeating `b` **exactly** `y` times (`b * y`) is a **substring** of the string formed by repeating `a` **exactly** `x` times (`a * x`). Otherwise, return `false`.

A **substring** is a contiguous **non-empty** sequence of characters within a string.

**Example 1:**

```
Input: a = "ab", b = "abab", x = 2, y = 1
Output: true
```

**Example 2:**

```
Input: a = "abc", b = "bc", x = 2, y = 3
Output: false
```

**Example 3:**

```
Input: a = "abcd", b = "cdab", x = 2, y = 1
Output: true
```

**Constraints:**

- `1 <= a.length <= 100`
- `1 <= b.length <= 100`
- `1 <= x <= 10^9`
- `1 <= y <= 10^9`
- `a` and `b` consist of lowercase English letters.

## Idea

Обе строки длиной до `10^11`, построить их нельзя. Но они периодические, и это сокращает обе размерности задачи.

**Сдвигов мало.** Сдвиг `offset + |a|` даёт ту же строку, что и `offset`, поэтому если вхождение есть, есть и вхождение со сдвигом меньше `|a|`. Заодно сдвиг обязан не превышать `total - pattern`, иначе `b * y` не поместится. Если `pattern > total`, ответ сразу `false`.

**Сравнивать надо мало.** При фиксированном сдвиге сравниваются строка `u` с периодом `|a|` и строка `v` с периодом `|b|`. По теореме Файна — Вильфа, если они совпали на `|a| + |b| - gcd(|a|, |b|)` символах, этот общий кусок имеет период `g = gcd`. Каждая строка определяется своим первым периодом, а он `g`-периодичен, поэтому и вся строка `g`-периодична. Первые `g` символов у них общие, значит, они совпадают и дальше.

Остаётся усечь образец до `compared = min(pattern, |a| + |b| - gcd)` символов, а текст до `min(|a| - 1, total - pattern) + compared` и вызвать `strings.Contains`. Длина текста задаёт ограничение на сдвиг сама: вхождение с большим сдвигом в обрезанный текст не поместится. Это важно именно при усечении: `"ab" * 10^9` и `"ba" * 10^9` дают `false`, хотя короткий `"ba"` в первой строке встречается.

Обычный наивный вариант, «построить несколько повторов и искать», здесь ломается как раз на этой границе, если не следить за местом для полного `b * y`. Тесты покрывают её на `x, y = 10^9`.

Проверки:

- 50 000 малых входов сверяются с настоящим построением `a * x` и `b * y`; тест требует минимум по 5000 ответов каждого вида.
- 5000 длинных входов сверяются с вариантом, сравнивающим `lcm(|a|, |b|)` символов: там пара позиций проходит полный цикл, поэтому корректность очевидна без теоремы.

Варианты замерены в одном бинарнике (`benchstat`, `-benchtime=100x`, `-count=5`, Apple M2 Pro, `p = 0.008`, `|a|` и `|b|` около 100):

| Вход            | `strings.Contains` | сравнение по модулю, Файн — Вильф | сравнение по модулю, `lcm` |
| --------------- | ------------------ | --------------------------------- | -------------------------- |
| `all-same-true` | 0.28 мкс           | 1.42 мкс                          | 22.10 мкс                  |
| `late-mismatch` | 0.72 мкс           | 22.82 мкс                         | 19.12 мкс                  |
| `coprime-false` | 0.73 мкс           | 9.45 мкс                          | 8.40 мкс                   |

`strings.Contains` быстрее ручного сравнения на 80–97%, хотя делает две аллокации. Граница Файна — Вильфа сокращает работу, только когда строки совпадают целиком (`all-same-true`, в 15 раз): при раннем несовпадении до границы дело не доходит, и там `lcm` даже немного быстрее (на 11–16%), причину я не выяснял. Замер короткий, а при таких временах это ни на что не влияет: все варианты укладываются в 25 мкс.

- Time: O(|a| + |b|), не зависит от `x` и `y`. Это ожидаемая оценка для `strings.Contains` на коротких строках; построение текста и образца линейно.
- Space: O(|a| + |b|)
